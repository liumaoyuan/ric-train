## 版本一：简历正文版

### 连锁餐饮 AI 系统 — AI 应用开发工程师

**技术栈：** Python / LangGraph / FastAPI / LangChain / Milvus / Redis / Vue 3 / Qwen / DeepSeek

**项目描述：** 面向 500 家门店的连锁中式快餐品牌，构建 AI 辅助管理系统。基于 LangGraph StateGraph 搭建聊天 Agent，集成 RAG 知识库检索、NL2SQL 数据分析、语义缓存、模型降级、SSE 流式等能力。系统覆盖营业分析、加盟商培训、风评监控、AI 聊天助手四大模块。

**核心贡献：**

- **Agent 架构设计**：主导从 LangChain AgentExecutor 到 LangGraph StateGraph 的技术选型与迁移，实现节点级重试（RetryPolicy）、状态持久化（Checkpointer）、人工审核介入（NodeInterrupt）等生产级特性
- **RAG 知识库系统**：搭建文档上传→分块→向量化→Milvus 检索→RAGAS 质量评估的完整链路，Hit Rate 目标 >90%，Faithfulness >85%，作为 CI 门禁防止质量回退
- **NL2SQL 安全体系**：设计三层安全防护（只读事务 + 表名白名单 + LIMIT 上限）+ 异常自愈机制，在功能与安全之间取得平衡
- **LLM 成本优化**：实现语义缓存（`semantic_cache:{role}:{md5}`，按场景区分 TTL）+ 多级模型降级（Qwen → DeepSeek → 固定兜底），月费用控制在 1000 元以内
- **流式交互**：基于 FastAPI SSE + 前端 ReadableStream 实现逐 token 流式输出，支持 AbortController 取消请求
- **RBAC 权限系统**：实现用户-角色-菜单三级权限模型，Agent 工具注册按角色动态过滤，加盟商/总部数据自然隔离

**量化成果：**

| 指标 | 提升 |
|------|------|
| 加盟商问题响应时间 | 4 小时 → <5 秒 |
| 差评响应时间 | 6~12 小时 → <1 小时 |
| 总部答疑工作量 | 减少 50% |
| LLM 月费用 | <1000 元 |
| RAG 检索有效率（Hit Rate） | >90% |

## 版本三：面试自我介绍版（1 分钟）

> 我主导了一个连锁餐饮 AI 系统的开发，面向 500 家门店提供 AI 辅助管理能力。
>
> 技术上，我选择了 LangGraph StateGraph 作为 Agent 框架，因为它相比传统的 AgentExecutor 提供了更精细的执行流控制和原生 Checkpointer/NodelInterrupt 能力。核心功能包括 RAG 知识库问答、NL2SQL 数据分析、语义缓存降本、SSE 流式交互。
>
> 印象比较深的几个技术挑战：一是 NL2SQL 的安全防护，我设计了只读事务 + 白名单 + LIMIT 三层防护配合异常自愈；二是 LLM 成本控制，通过语义缓存和模型降级把月费用控制在千元以内；三是海量数据的分层分析策略，SQL 聚合 + LLM 解读而不是直接把原始数据塞给大模型。
>
> 项目同时集成了 RAGAS 质量评估闭环，每次知识库更新自动验证检索质量，Hit Rate 目标 90% 以上。

## 简历使用建议

1. **量化优先**：每个成果尽量带数字（500 家门店、4 小时→5 秒、成本 1000 元）
2. **技术深度**：不要只列技术名词，要体现对比选型思考（为什么 LangGraph 不是 AgentExecutor）
3. **工程意识**：安全防护（NL2SQL 三层安全）、成本控制（语义缓存）、可观测性（RAGAS + LangFuse）这些是面试加分项
4. **诚实边界**：标注为"设计"或"搭建"而非"上线运营"，避免面试被追问实际在线数据
