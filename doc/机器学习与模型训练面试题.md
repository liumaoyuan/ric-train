## 一、机器学习基础

### Q1：监督学习、无监督学习、半监督学习、自监督学习的区别？

| 类型 | 数据 | 目标 | 典型任务 |
|------|------|------|----------|
| **监督学习** | (特征, 标签) 对 | 学习 X→Y 映射 | 分类、回归 |
| **无监督学习** | 只有特征 X | 发现数据内在结构 | 聚类、降维、异常检测 |
| **半监督学习** | 少量有标签 + 大量无标签 | 利用无标签数据提升泛化 | 同监督学习 |
| **自监督学习** | 无人工标签 | 从数据自身构造监督信号 | 预训练（BERT 的 MLM、GPT 的 CLM） |

**面试加分：** 自监督学习是大模型成功的核心——用数据自身的结构生成标签（GPT 的 next token prediction、BERT 的 masked language modeling），不需要人工标注。

---

### Q2：偏差-方差权衡 (Bias-Variance Tradeoff) 是什么？

**核心概念：**
- **偏差 (Bias)**：模型对真实关系的简化程度。高偏差 → 欠拟合
- **方差 (Variance)**：模型对训练数据波动的敏感程度。高方差 → 过拟合

```
高偏差（欠拟合）            平衡点              高方差（过拟合）
    │                         │                     │
    └─────────────────────────┴─────────────────────────→ 模型复杂度
训练误差高                    训练≈测试             训练误差极低
测试误差高                                           测试误差高
```

**面试加分：** 实际工作中一般不看理论的 U 型曲线，而是用"训练集误差 vs 验证集误差"的变化趋势来判断。训练误差下降但验证误差开始上升 → 过拟合了。

### Q3：L1 和 L2 正则化的区别？为什么 L1 产生稀疏解？

| 维度 | L1 (Lasso) | L2 (Ridge) |
|------|-------------|-------------|
| 公式 | Loss + λ∑\|w\| | Loss + λ∑w² |
| 解的特性 | 稀疏（很多权重=0） | 权重均匀缩小（趋近 0 但不等于 0） |
| 几何解释 | 菱形约束区域，尖角与等高线相切 | 圆形约束区域，光滑接触 |
| 适用场景 | 特征选择、高维稀疏 | 防止过拟合、处理多重共线性 |

**为什么 L1 产生稀疏解？** L1 的约束区域是菱形（有尖角），当目标函数的等高线碰到尖角时，对应维度系数被压缩到 0。L2 的圆形约束区域没有尖角，所以权重趋近 0 但不为 0。

---

### Q4：交叉熵损失函数的推导？为什么分类用交叉熵不用 MSE？

**交叉熵：** `L = -∑y_i·log(p_i)`
- 二分类：`L = -[y·log(p) + (1-y)·log(1-p)]`

**为什么分类用交叉熵：**
- MSE 对输出层的梯度包含 `σ'(z)` 项（sigmoid 导数），在饱和区梯度接近于 0，收敛极慢
- 交叉熵的梯度正比于 `(p - y)`，误差越大梯度越大，收敛更快
- 从信息论角度：交叉熵衡量两个分布的差异，分类本质是概率分布匹配

---

### Q5：什么是过拟合？怎么检测和防止？

**检测：** 训练集误差持续下降，验证集误差开始上升 → 过拟合

**防止策略：**

| 方法 | 原理 | 实操 |
|------|------|------|
| 正则化 (L1/L2) | 限制权重大小 | L2 weight decay 最常用 |
| Dropout | 训练时随机丢弃神经元，相当于集成学习 | 通常 p=0.1~0.5 |
| Early Stopping | 验证集不改善时停止训练 | patience=3~10 个 epoch |
| 数据增强 | 增加训练数据多样性 | 图像翻转/裁剪、文本回译 |
| 减少模型参数量 | 降低模型容量 | 减少层数/隐层维度 |
| Label Smoothing | 避免模型过度自信 | 从 hard label 变 soft label |

**面试加分：** Dropout 本质上是训练了多个共享权重的子网络，推理时相当于对这些子网络的几何平均做近似（权重缩放）。

### Q6：什么是 AUC-ROC？AUC=0.5 和 AUC=1.0 分别代表什么？

- **ROC 曲线**：以 FPR（假正率）为横轴、TPR（真正率/召回率）为纵轴的曲线
- **AUC**：ROC 曲线下的面积

| AUC 值 | 含义 |
|---------|------|
| 1.0 | 完美分类器 |
| 0.9~1.0 | 优秀 |
| 0.8~0.9 | 良好 |
| 0.7~0.8 | 一般 |
| 0.5 | 随机猜测 |
| < 0.5 | 比随机还差（可能标签反了） |

**AUC 的统计学含义：** 随机选一个正样本和一个负样本，模型对正样本的打分高于负样本的概率。所以 AUC 对样本不平衡不敏感。

---

### Q7：常见的评估指标有哪些？什么时候用 Precision/Recall 什么时候用 Accuracy？

| 指标 | 公式 | 适用场景 |
|------|------|----------|
| Accuracy | (TP+TN)/(TP+TN+FP+FN) | 类别平衡 |
| Precision | TP/(TP+FP) | 强调"不准误报"（垃圾邮件过滤） |
| Recall/TPR | TP/(TP+FN) | 强调"不准漏报"（疾病筛查） |
| F1-Score | 2×P×R/(P+R) | Precision+Recall 的综合 |
| Specificity | TN/(TN+FP) | 负样本的识别能力 |

**核心原则：** 类别不平衡时不要用 Accuracy。100 个样本 99 个正类，全部预测为正 Accuracy=99% 但毫无意义。

### Q8：XGBoost vs LightGBM vs 随机森林的区别？

| 维度 | 随机森林 | XGBoost | LightGBM |
|------|----------|---------|----------|
| 类型 | Bagging | Boosting | Boosting |
| 基学习器 | 决策树（独立训练） | 决策树（串行） | 决策树（串行） |
| 分裂策略 | 随机选特征子集 | pre-sorted（预排序） | histogram（直方图） |
| 训练速度 | 快（可并行） | 中等 | 快（GOSS+EFB） |
| 精度 | 中等 | 高 | 高（与 XGBoost 接近） |
| 过拟合风险 | 低 | 中（可调正则控制） | 中 |
| 类别特征 | 需编码 | 需编码 | 原生支持 |

**面试加分：** 实际选型经验——数据量 < 1 万行用 XGBoost（精度好），> 10 万行用 LightGBM（快），随机森林适合做 baseline 和高维稀疏特征。

### Q9：PCA 的原理？什么时候用？

**原理：**
1. 数据中心化（减去均值）
2. 计算协方差矩阵
3. 特征值分解，取最大的 k 个特征值对应的特征向量
4. 将数据投影到这些特征向量组成的空间

**用途：**
- 降维可视化（降到 2D/3D）
- 去除噪声（丢弃小方差维度）
- 缓解维度灾难
- 加速后续算法

**缺点：** PCA 是无监督的，不考虑标签信息，PCA 保留的方向不一定对分类任务有用。此时可以用 LDA（有监督降维）。

---

### Q10：什么是 K-Fold Cross Validation？为什么要用？

把数据分成 K 份，轮流用 K-1 份训练、1 份验证，重复 K 次，结果取平均。

- **K=5 或 10** 最常用
- **Stratified K-Fold**：保持每折中类别比例与原始数据一致（分类任务必用）
- **用途：** 小数据集上更可靠的模型评估，减少单次划分的偶然性

## 二、模型训练与优化

### Q11：梯度下降的几种变体 (BGD/SGD/Mini-batch) 的区别？

| 变体 | 每次更新使用的样本 | 特点 |
|------|-------------------|------|
| BGD (Batch GD) | 全部样本 | 准确但慢，无法在线学习 |
| SGD (Stochastic GD) | 1 个样本 | 快但有噪声，震荡大 |
| Mini-batch GD | batch size 个样本 | 折中，最常用（32/64/128/256） |

**Mini-batch 的 batch size 怎么选？**
- 太大（>512）：收敛稳定但泛化差，占显存多
- 太小（<16）：梯度噪声大，收敛慢
- 经验值：32~256，且尽量用 2 的幂次（硬件优化）

---

### Q12：常用的优化器有哪些？Adam 为什么流行？

| 优化器 | 核心思想 | 特点 |
|--------|----------|------|
| **SGD+Momentum** | 累积历史梯度方向 | 加速收敛，抑制震荡 |
| **AdaGrad** | 自适应学习率，稀疏特征大更新 | 适合稀疏数据，但学习率单调递减到 0 |
| **RMSProp** | 梯度平方的指数移动平均 | 解决 AdaGrad 学习率消失问题 |
| **Adam** | Momentum + RMSProp + 偏差修正 | 默认推荐，自适应学习率+动量 |
| **AdamW** | Adam + 解耦 weight decay | 比 Adam 泛化更好（主流 LLM 训练都用它） |

**Adam 为什么流行：**
1. 自适应学习率：不用怎么调学习率就能收敛
2. 自带动量：收敛快
3. 对梯度缩放不敏感：适合大规模分布式训练

**但 Adam 可能泛化不如 SGD：** 某些 CV 任务中 SGD+Momentum 调好学习率和 schedule 后泛化更好。LLM 预训练主流用 AdamW。

---

### Q13：学习率调节策略有哪些？

| 策略 | 行为 | 适用 |
|------|------|------|
| Step Decay | 每 N 个 epoch 乘 γ（如 ×0.1） | 传统 CV |
| Cosine Annealing | 余弦曲线从 η_max 降到 η_min | 现代深度学习 |
| Cosine with Warmup | 前 N 步线性上升到 η_max，再余弦下降 | **LLM 预训练标配** |
| ReduceLROnPlateau | 验证 loss 不降时减学习率 | 通用调参 |
| OneCycle | 先升后降 | 快速训练 |

**为什么 LLM 训练需要 Warmup？**
- 初始时模型参数随机，梯度方向不稳定
- 直接大学习率会导致震荡/发散
- 线性 warmup（通常 500~2000 步）让优化器先稳定方向再加大步长

---

### Q14：深度学习模型权重初始化方法？

| 方法 | 公式 | 适用激活函数 |
|------|------|-------------|
| Xavier/Glorot | Var = 1/(n_in + n_out) | tanh, sigmoid |
| He/Kaiming | Var = 2/n_in | ReLU, PReLU |
| LeCun | Var = 1/n_in | SELU |

**核心原则：** 初始化要保证前向/反向传播时方差不爆炸也不消失。选错初始化会导致梯度消失/爆炸，模型不收敛。

**LLM 常用：** 标准差 0.02 的正态分布（小初始化，配合 Pre-LN 稳定训练）。

---

### Q15：什么是梯度消失和梯度爆炸？怎么解决？

**梯度消失：** 深层网络梯度趋近 0，浅层参数几乎不更新
**梯度爆炸：** 梯度指数级增长，参数更新过大导致 NaN

| 问题 | 原因 | 解决方案 |
|------|------|----------|
| 梯度消失 | sigmoid/tanh 饱和区、深层网络 | ReLU、残差连接（ResNet/LN）、LayerNorm |
| 梯度爆炸 | 深层网络、权重过大 | 梯度裁剪 (gradient clipping)、权重初始化 |

**梯度裁剪的两种方式：**
- **按值裁剪**：`clip_value`（min, max）
- **按范数裁剪**：`clip_norm`，`g = g * threshold / ||g||`（更常用，LLM 预训练必备）

---

### Q16：Batch Normalization vs Layer Normalization？

| 维度 | BatchNorm | LayerNorm |
|------|-----------|-----------|
| 归一化维度 | 对 batch 维度归一化，对每个特征独立 | 对每个样本的特征维度归一化 |
| 依赖 batch size | 依赖（batch 小效果差） | 不依赖 |
| 训练/推理差异 | 训练用 batch 统计量，推理用全局均值 | 一致 |
| 序列长度变化 | 不适用（长度变化影响统计量） | 适用 |
| 适用场景 | CV（CNN） | NLP / Transformer |

**为什么 Transformer 用 LayerNorm 不用 BatchNorm？**
- NLP 任务中序列长度可变，BatchNorm 的 batch 统计量不稳定
- LayerNorm 每个样本独立归一化，不受 batch 中其他样本影响
- 训练和推理行为一致

### Q17：数据不平衡怎么处理？

| 方法 | 做法 | 注意 |
|------|------|------|
| 重采样 | 过采样少数类 / 欠采样多数类 | 过采样易过拟合，欠采样丢信息 |
| 类别权重 | loss 中少数类乘大权重 | 简单有效 |
| Focal Loss | 降低易分类样本权重 | 目标检测常用 |
| 数据增强 | 合成少数类数据 (SMOTE) | 注意生成质量 |
| 异常检测 | 改用 Isolation Forest 等 | 本质换任务 |

**经验：** 业务场景先分清是"类别不平衡"还是"罕见事件"。类别不平衡可以用权重/采样解决；罕见事件（如欺诈检测）要考虑换模型或做异常检测。

### Q18：什么是 Multi-task Learning？什么时候用？

多个相关任务共享一个模型的表示层（共享底层 + 独立上层）。

**好处：**
- 共享表示，数据量小的任务受益
- 正则化效果，防止过拟合
- 多视角学习，鲁棒性更好

**适用场景：**
- NLP 中同时做 NER + 关系抽取 + 事件抽取
- 推荐系统中同时预测 CTR + CVR
- LLM 预训练本身就是多任务（预测各种 token）

**面试加分：** 多任务学习的核心挑战是任务间的冲突和梯度平衡。三个关键设计：1) 共享 vs 独立参数的比例；2) 各任务 loss 的权重调节；3) 梯度冲突检测（PCGrad 等方法）。

### Q19：什么是知识蒸馏 (Knowledge Distillation)？

用一个大模型（Teacher）的输出作为软标签来训练小模型（Student）。

```
教师模型（大） → softmax(T/τ)  →  软标签（温度 τ 控制平滑度）
学生模型（小） → softmax(S/τ)  →  学生logits

损失 = α × 硬标签损失(CE) + (1-α) × τ² × 蒸馏损失(KL散度)
```

**为什么有效：** 教师模型的软标签包含了类别间的关系信息（"猫"和"虎"比"猫"和"车"更相似），比硬标签（one-hot）信息更丰富。

**应用场景：** 模型压缩加速（BERT→TinyBERT）、联邦学习（教师模型不下发）。

### Q20：模型训练时 Loss 不下降怎么办？

排查路径：

1. **检查数据**：标签是否正确？数据预处理有 bug？特征是否标准化？
2. **检查模型**：梯度是否为 0？输出层激活函数对不对？loss 函数对不对？
3. **检查训练配置**：学习率太大/太小？batch size 太大？优化器选对了？
4. **过拟合测试**：先在一个小 batch 上训练到 loss=0（验证模型能记住），再上全量数据
5. **检查数值稳定性**：有没有 NaN？gradient clipping 是否需要？

**最实用的 debug 方法：** 先在小数据集上过拟合（验证模型没问题），再逐步加大数据。

## 三、模型微调 (Fine-tuning)

### Q21：Full Fine-tuning vs PEFT (高效微调) 的区别？

| 维度 | Full Fine-tuning | PEFT (LoRA / Adapter / Prefix-tuning) |
|------|-----------------|---------------------------------------|
| 参数量 | 更新全部参数 | 只更新少量参数（< 1%） |
| 显存 | 高（需存全部优化器状态） | 低（冻结原参数） |
| 训练速度 | 慢 | 快 |
| 效果 | 好（充分适配） | 接近 Full FT |
| 多任务部署 | 每个任务一个完整模型 | 基座模型共享 + 多个小 adapter |
| 灾难性遗忘风险 | 高 | 低（原始权重不变） |

**面试加分：** PEFT 的核心理念是"LLM 学到的通用知识足够好，微调只需要在低秩子空间中找到适配方向"。LoRA 假设权重更新的秩较低（rank=8~64），将 ΔW 分解为两个小矩阵相乘。

---

### Q22：LoRA 的原理？rank 怎么选？

**原理：**
- 冻结原始权重 W₀
- 在 W₀ 旁插入低秩分解矩阵 `B·A`（B：d×r，A：r×k，r << min(d,k)）
- 前向：`h = W₀·x + α·(B·A)·x`（α 为 scaling 系数）
- 只训练 B 和 A

**LoRA 的推理合并：** 训练完成后可以 `W = W₀ + α·B·A` 合并回原权重，**推理时零额外延迟**。

**rank 选择经验：**
| rank | 适用 |
|------|------|
| 1~4 | 简单适配（风格迁移、格式控制） |
| 8~16 | 通用微调（默认） |
| 32~64 | 复杂任务（代码生成、数学推理） |
| > 64 | 收益递减，不如 full FT |

**面试加分：** LoRA 通常只应用在 attention 的 Q/K/V/O 四个投影矩阵上，不对 MLP 层做。在多个线性层上加 LoRA，效果优于只在单层加。

---

### Q23：什么是 QLoRA？和 LoRA 的区别？

QLoRA = LoRA + 4-bit NormalFloat (NF4) 量化 + Double Quantization + Paged Optimizer

| 对比 | LoRA | QLoRA |
|------|------|-------|
| 基座精度 | FP16/BF16 | NF4 (4-bit) |
| 显存节省 | — | ~4x（70B 模型 48GB 可训） |
| 效果 | — | 与 LoRA 几乎持平（< 1% 差距） |
| 速度 | 更快 | 略慢（量化/反量化开销） |

**QLoRA 为什么效果不差：** 冻结的量化权重仍然保留了大部分信息，LoRA 学习的是残差适配，不依赖基座的精确数值。

---

### Q24：微调时显存怎么估算？Batch size 与显存的关系？

以 LLaMA-7B (BF16) 为例，Full FT 时显存主要由几部分组成：

| 组件 | 显存占用（约） | 说明 |
|------|---------------|------|
| 模型权重 | 14 GB | 7B × 2 bytes (BF16) |
| 梯度 | 14 GB |  |
| 优化器状态 (Adam) | 28 GB | 每参数 4 bytes (m + v) |
| 激活值 | variabl | 取决于 batch size × 序列长度 |
| 总显存（估算） | ~60+ GB | 仅 7B 模型 Full FT |

**经验公式：**
- Full FT 显存 ≈ 模型参数量 × (2 + 2 + 4 或 0) × 1.2
  - Adam: 2(权重) + 2(梯度) + 4(m+v) = **8 bytes/参数** × 1.2 = **~9.6 bytes/参数**
  - SGD: 2 + 2 = 4 bytes/参数
- LoRA 显存 ≈ 推理显存 + 可训练参数量 × 8 × 1.2
  - 通常仅需 2~8 GB 额外显存

**减少显存技巧：**
- Gradient Checkpointing (用时间换空间，激活值从 O(L) 降到 O(√L))
- LoRA + 4-bit 量化 (QLoRA)
- ZeRO Stage 3（分布式训练时每卡只存部分参数）

### Q25：微调时灾难性遗忘 (Catastrophic Forgetting) 怎么缓解？

**定义：** 微调新任务导致模型遗忘预训练学到的通用知识

**缓解策略：**

| 方法 | 做法 |
|------|------|
| **PEFT (LoRA)** | 冻结原参数，只训练低秩 adapter，原始知识不受影响 |
| **EWC (Elastic Weight Consolidation)** | 对重要参数加正则约束，不让它们偏离太远 |
| **Replay / Memory** | 微调时混入 10~30% 预训练数据 |
| **Multi-task Learning** | 新任务 + 原任务联合训练 |
| **Freeze 浅层** | 只微调高层（Transformer 的后几层） |

**经验：** PEFT + 少量预训练数据混合效果最好，实现简单。SFT 阶段混入 5~20% 预训练数据很常见。

---

### Q26：什么是 Instruction Tuning (指令微调)？

用 (instruction, input, output) 格式的数据微调 LLM，让模型学会遵循指令。

**与预训练的区别：**
- 预训练：Predict next token on web corpus
- 指令微调：Follow instructions on curated (指令, 回答) pairs

**关键因素：**
- **数据质量 > 数量**：几千条高质量指令数据往往比几十万条爬虫数据好
- **多样性**：覆盖各类任务（写作、翻译、推理、编程、QA 等）
- **格式一致性**：统一模板，减少格式干扰

**常见指令数据格式：**
```
### Instruction:
{task description}

### Input:
{optional input context}

### Response:
{expected output}
```

### Q27：RLHF (Reinforcement Learning from Human Feedback) 流程？

```
Step 1: SFT (Supervised Fine-tuning)
  收集人工撰写的（prompt, response）对 → 指令微调基座模型

Step 2: Reward Model Training
  对同一 prompt 生成多个 response → 人工排序
  → 训练 Reward Model 预测人类偏好

Step 3: PPO RL Training
  SFT 模型做 Policy，Reward Model 给奖励
  PPO 优化 → 参考 KL 惩罚防止偏离太远
```

**DPO (Direct Preference Optimization)** 是 RLHF 的简化替代：
- 不需要训练 Reward Model
- 直接用偏好对 (chosen, rejected) 定义 loss
- 数学上等价于 RLHF 但实现更简单

**面试加分：** RLHF 的 PPO 训练非常不稳定（reward hacking、mode collapse），需要仔细调参和 KL 约束。DPO 收敛更稳定但需要高质量的偏好对。

### Q28：什么时候应该微调？什么时候应该用 RAG？

| 场景 | 推荐方案 | 原因 |
|------|----------|------|
| 知识频繁更新（制度、菜谱） | **RAG** | 换文档就行，不需要重新训练 |
| 需要模型改变输出格式/风格 | **微调** | 让模型学会特定的输出结构 |
| 长尾知识问答 | **RAG** | 微调记不住太多细节知识 |
| 工具调用/Function Calling | **微调** | 让模型学会结构化输出 |
| 低延迟要求 | **RAG**（不改变基座） | 微调后模型通常更大 |
| 隐私数据不出域 | **RAG** | 文档在本域，LLM 在云上 |
| 模型行为对齐（安全/价值观） | **微调 + RLHF** | RAG 做不到行为对齐 |

**最佳实践：** 两者不是互斥的。先 RAG 做知识注入 + 再微调做能力适配，效果最好。

## 四、模型部署与服务

### Q29：模型部署的性能指标有哪些？

| 指标 | 含义 | 优化目标 |
|------|------|----------|
| **Latency (P50/P95/P99)** | 响应延迟 | 越低越好 |
| **Throughput** | 每秒处理请求数 | 越高越好 |
| **TTFT (Time to First Token)** | 首 token 延迟 | LLM 流式场景关键 |
| **TPOT (Time per Output Token)** | 每 token 生成时间 | 影响用户体验 |
| **显存占用** | 推理时 GPU 显存 | 影响部署密度 |
| **QPS (Queries per Second)** | 每 GPU 每秒查询 | 成本核算依据 |

**面试加分：** LLM 部署最关键的指标是 TTFT（首 token 延迟），直接影响用户体验。它受 prompt 处理（prefill 阶段）速度影响最大。

### Q30：模型量化 (Quantization) 的原理和常见方法？

**原理：** 将 FP16/BF16 的模型权重用更低位数的整数表示（INT8/INT4），减少显存占用和计算量。

**常见方法：**

| 方法 | 精度 | 显存节省 | 效果保留 |
|------|------|----------|----------|
| **GPTQ** | 4-bit | ~4x | 好 |
| **GGUF (llama.cpp)** | 2~8-bit 可变 | 2~8x | 好（小模型损失较大） |
| **AWQ** | 4-bit | ~4x | 好（优于 GPTQ） |
| **BitsAndBytes (NF4)** | 4-bit | ~4x | 好（QLoRA 方案） |
| **SmoothQuant** | 8-bit | ~2x | 几乎无损 |

**量化精度 vs 模型大小：**
- FP16/BF16 (16-bit)：基准，无损
- INT8 (8-bit)：几乎无损，PPL 增加 < 0.1
- INT4 (4-bit)：略微损失，PPL 增加 ~0.3~0.5
- INT2/3：明显损失

**量化方式：**
- **PTQ (Post-Training Quantization)**：训练后直接量化，不需要数据
- **QAT (Quantization-Aware Training)**：训练中模拟量化，精度更好但需要训练

### Q31：vLLM / TensorRT-LLM 为什么比原生推理快？

核心优化技术：

| 技术 | 说明 | 加速效果 |
|------|------|----------|
| **PagedAttention** | 类似虚拟内存管理 KV Cache，消除碎片和冗余 | 显存利用率提升至 ~95% |
| **Continuous Batching** | 请求到了就加入当前 batch，不等满 | 吞吐量提升 2~4x |
| **CUDA Kernel 融合** | 算子融合减少 kernel launch 开销 | 延迟降低 1.5~2x |
| **KV Cache 量化** | Cache 用 FP8/INT8 存储 | 显存减半 |
| **Speculative Decoding** | 小模型先猜，大模型验证 | 延迟降 2~3x |

**面试加分：** PagedAttention 是 vLLM 的核心创新——传统做法为每个请求预分配最大长度的连续显存（浪费 60%+），PagedAttention 按页分配，用块表做地址映射，类似 OS 的虚拟内存。

### Q32：Prompt Prefill 和 Decode 阶段的优化区别？

LLM 推理分为两个阶段：

| 阶段 | 特点 | 瓶颈 | 优化方向 |
|------|------|------|----------|
| **Prefill** | 并行计算 prompt 所有 token 的 attention | 计算密集 | FlashAttention、并行处理 |
| **Decode** | 逐 token 生成（自回归） | 内存密集 | KV Cache、Speculative Decoding |

**Prefill 阶段优化重点：**
- FlashAttention（减少 HBM 读写）
- Prompt caching（复用相同 prompt prefix 的 KV Cache）
- 批处理（把多个 prompt 拼在一起计算）

**Decode 阶段优化重点：**
- KV Cache（避免重复计算已生成 token 的 K/V）
- PagedAttention（高效管理 KV Cache 显存）
- Speculative Decoding（一次 decode 验证多个 token）

### Q33：分布式推理的几种策略？

| 策略 | 原理 | 适用 |
|------|------|------|
| **张量并行 (TP)** | 将单个 Transformer 层切分到多卡 | 单模型过大单卡放不下（单机多卡） |
| **流水线并行 (PP)** | 不同层放在不同 GPU | 模型太深（跨机器） |
| **数据并行 (DP)** | 每卡放完整模型，分不同请求 | 高吞吐量（最简单的扩展方式） |

LLM 的分布式推理典型组合：**TP + DP** 最常见。TP 解决单卡放不下的问题，DP 提升吞吐量。

| 组合 | 配置 | 
|------|------|
| TP=8 | 8 卡跑一个模型，延迟最低 |
| TP=4 + DP=2 | 4 卡放一个模型 × 2 个副本，平衡延迟和吞吐 |
| TP=8 + DP=N | 多个 8 卡副本，高吞吐 |

### Q34：什么是 KV Cache？为什么重要？

自回归生成时，每步计算 attention 都需要所有之前 token 的 K 和 V。KV Cache 就是把之前步骤算好的 K/V 矩阵存下来，避免重复计算。

**计算公式（每步）：**
- 无 KV Cache：需要重新计算 1~t 步的 attention → O(t²)
- 有 KV Cache：只需要计算第 t 步的 attention → O(t)

**KV Cache 的显存占用：**
```
2 (K和V) × L (层数) × d (head_dim) × nh (head数) × b (batch) × s (序列长度) × 2 bytes (FP16)
```
例如 LLaMA-70B：每 token 需要 ~50 KB 的 Cache，生成 4096 tokens × batch=64 → 50KB × 4096 × 64 ≈ 13 GB

### Q35：什么是 FlashAttention？

FlashAttention 是一种**精确的 attention 计算算法**（不是近似），通过分块 (tiling) 技术减少 HBM（高带宽内存）和 SRAM 之间的读写次数。

**核心思想：**
- 传统 Attention：S = Q·Kᵀ → 写 HBM → softmax → 写 HBM → P·V → 写 HBM (多次 HBM 读写)
- FlashAttention：在 SRAM 中分块计算，一次读取完成整个 block 的 attention，大幅减少 HBM 访问

**收益：**
- 2~4x 加速
- 显存从 O(N²) 降到 O(N)（不需要存储完整的 attention 矩阵）
- 精确结果（不是近似）

**FlashAttention-2** 进一步优化线程调度，达到 A100 理论峰值 ~70% 利用率。

## 五、大模型基础 (LLM)

### Q36：什么是 Autoregressive Language Model（自回归语言模型）？

自回归 = 预测序列中**下一个 token**，已生成的 token 作为下一个预测的条件。

```
P(x) = P(x₁) · P(x₂|x₁) · P(x₃|x₁,x₂) · ... · P(xₙ|x₁,...,xₙ₋₁)
```

**GPT 系列就是自回归模型**——从左到右依次预测下一个 token（Causal LM）。

**与 BERT 的区别：**
- GPT：单向注意力（只能看到左边），自回归
- BERT：双向注意力（能看到左右两侧），去噪自编码

**为什么 GPT 更成功：**
- 自回归目标直接对应"生成"能力，不需要额外 task head
- Scaling Law 表明自回归 loss 随计算量/数据/参数量可预测下降
- 推理时就是自回归生成，训练和推理目标一致

---

### Q37：什么是 Scaling Law (缩放定律)？

OpenAI 2020 年发现的经验规律：**LLM 的性能（loss）与模型参数量（N）、数据量（D）、计算量（C）之间呈幂律关系**。

```
Loss ∝ N^(-α) + D^(-β) + C^(-γ)   (α≈0.076, β≈0.103, γ≈0.050)
```

**核心发现：**
1. 模型越大，效果越好（但收益递减）
2. 数据越多，效果越好（但收益递减）
3. 同时扩大模型和数据比只扩一个更有效
4. **训练不足的大模型不如训练充分的小模型**

**Chinchilla 法则 (DeepMind 2022)：** 对于计算预算 C，最优的参数量和数据量关系是：**每 1 个参数需要 ~20 个 token**。这意味着很多模型（如 LLaMA-1）实际上训练不足。

| 模型 | 参数量 | 训练 token | Chinchilla 建议 |
|------|--------|-----------|-----------------|
| LLaMA-65B | 65B | 1.4T | ✅ 接近 20× |
| GPT-3 | 175B | 300B | ❌ 严重不足（应为 3.5T） |
| LLaMA-3-70B | 70B | 15T | ✅ 远超 |

### Q38：什么是 Hallucination（幻觉）？产生原因和缓解方法？

**定义：** LLM 生成看似合理但实际错误的内容。

**产生原因：**
1. **训练数据局限**：训练数据中不存在或矛盾的信息
2. **自回归误差累积**：一步错，步步错
3. **模型过拟合记忆**：记住了训练集中的错误关联
4. **解码策略问题**：追求高概率的 token 不一定是最正确的
5. **知识截止**：训练后的新事件模型不知道

**分类：**
- **事实性幻觉**：说错了事实（"法国首都是伦敦"）
- **忠实性幻觉**：不遵循指令/上下文（问你 A 答 B）

**缓解方法：**

| 方法 | 说明 |
|------|------|
| **RAG** | 检索外部知识作为上下文，最有效 |
| **Prompt Engineering** | "如果你不确定，就说不知道" |
| **Chain-of-Thought** | 推理过程可见，减少跳跃性错误 |
| **温度调低** | 减少随机性（推理时 temperature=0） |
| **Consistency Check** | 多次采样取一致结果 (Self-Consistency) |
| **工具增强** | 计算、搜索交给外部工具 |

**经验：** RAG 是最实用的幻觉缓解方案。纯靠 Prompt 无法根除幻觉，因为模型本身不具备"不知道"的能力。

### Q39：什么是 Context Window？上下文窗口的限制和扩展方法？

**定义：** LLM 一次能处理的最大 token 数量。

| 模型 | 最大上下文 |
|------|-----------|
| GPT-3 | 2K (2048) |
| GPT-4 | 8K / 32K / 128K |
| Claude 3 | 200K |
| Gemini 1.5 | 1M (1000K) |
| LLaMA-3 | 8K |

**上下文窗口的限制因素：**
1. **Attention 计算量 O(L²)**：序列长度翻倍，计算量翻 4 倍
2. **显存 O(L²)**：KV Cache 与长度二次增长
3. **训练数据中的长度分布**：大部分训练文本较短，长文本稀缺
4. **位置编码的泛化**：RoPE 等位置编码在训练长度之外的泛化能力有限

**扩展上下文的方法：**

| 方法 | 原理 |
|------|------|
| **位置编码外推** | RoPE 的 base 调大（如 10000→500000）+ NTK-aware 插值 |
| **YaRN** | 对 RoPE 频率做缩放，减少 token 位置混淆 |
| **LongLoRA** | shifted sparse attention + LoRA 微调 |
| **Ring Attention** | 分布式 attention，跨设备分块计算 |
| **压缩 / 摘要** | 总结历史内容后替换（如 summary_node） |

### Q40：什么是 Prompt Engineering？有哪些高级技巧？

| 技巧 | 说明 | 示例 |
|------|------|------|
| **Few-shot** | 给几个示例 | "翻译以下句子：\nEnglish→中文\nHello→你好\nGoodbye→" |
| **Chain-of-Thought (CoT)** | 要求逐步推理 | "让我们一步步思考" |
| **Self-Consistency** | 多次 CoT 取多数 | 适用数学/推理题 |
| **Tree-of-Thought (ToT)** | 同时探索多条推理路径 | 更适合复杂规划 |
| **ReAct** | 推理 + 工具交替 | Agent 框架基础 |
| **Role Prompting** | 设定角色 | "你是一名资深律师" |
| **System Prompt** | 设定系统级约束 | "用中文回答，不超过 200 字" |

**经验：** System Prompt 设计最容易被忽视的坑——**不要把 System Prompt 和用户消息放在同一个列表中持久化**，否则恢复会话时会累积冗余的 SystemMessage。

### Q41：模型的 Temperature / Top-p / Top-k 采样有什么区别？

所有采样参数都是控制**生成多样性**的手段。

| 参数 | 行为 | 取值影响 |
|------|------|----------|
| **Temperature** | 缩放 logits 后再做 softmax | T→0：贪心；T→大：均匀随机 |
| **Top-k** | 只保留概率最高的 k 个 token | k=1 ≈ 贪心；k=50：适当的多样性 |
| **Top-p (Nucleus)** | 保留累积概率达到 p 的 token | p=0.9：保留 90% 概率质量的 token |
| **Repetition Penalty** | 降低已生成 token 的概率 | 1.0=无惩罚，1.1~1.2=适当惩罚 |

**推荐经验：**
- 推理/事实问答：T=0（贪心解码）
- 创意写作：T=0.7~0.9 + Top-p=0.95
- 代码生成：T=0.2~0.4

### Q42：什么是 Mixture of Experts (MoE)？

MoE 将模型分解为多个"专家"子网络，每次推理只激活其中的一部分。

```
输入 → Router → 选择 Top-K 专家 → 被选专家的输出加权求和
```

**经典 MoE 模型：**
| 模型 | 总参数量 | 活跃参数 | 专家数 |
|------|---------|---------|--------|
| Mixtral 8×7B | ~47B | ~12.9B | 8 |
| DeepSeek-V2 | ~236B | ~21B | MoE |
| GPT-4 | 传闻 1.7T | ? | 传闻 8 个 |

**MoE 的好处：**
- 总参数量大（知识容量大），但推理计算量只等于活跃参数
- 每个专家可以 specialize（自动分化）
- 训练时每个 token 只激活部分专家，计算效率高

**MoE 的挑战：**
- 负载不均衡：某些专家收到更多 token（需要 aux loss 约束）
- 通信开销：专家可能分布在不同的 GPU 上
- 微调更复杂（Router 同步训练）

## 六、Transformer 架构

### Q43：Transformer 的整体架构？

```
输入序列 → Token Embedding + Positional Encoding
    ↓
  [Encoder × N]              [Decoder × N]
  ├── Multi-Head Self-Attn   ├── Masked Multi-Head Self-Attn
  ├── Add & LayerNorm         ├── Add & LayerNorm
  ├── Feed Forward (MLP)     ├── Cross-Attention（与 Encoder 输出）
  └── Add & LayerNorm         ├── Add & LayerNorm
                              ├── Feed Forward (MLP)
                              └── Add & LayerNorm
    ↓
  Linear → Softmax → 输出概率
```

**每个子层的共性结构：**
```
output = LayerNorm(x + Sublayer(x))
```
这就是**残差连接 + Pre-LayerNorm**（现代 Transformer 的标准做法）。

---

### Q44：Self-Attention 的计算过程？

```
给定输入 X (n × d_model)
1. Q = X·W_Q, K = X·W_K, V = X·W_V   (W_Q, W_K, W_V: d_model × d_k)
2. Attention(Q,K,V) = softmax(Q·Kᵀ / √d_k) · V
   - Q·Kᵀ: 相似度矩阵 (n × n)
   - /√d_k: 缩放，防止内积过大导致 softmax 进入极端区域
   - softmax: 按行归一化 → 注意力权重
   - ·V: 加权求和 → 输出 (n × d_v)
```

**为什么除以 √d_k：** 假设 q 和 k 是均值为 0、方差为 1 的独立随机变量，点积的方差 = d_k。除以 √d_k 后方差回到 1，softmax 不会进入梯度极小的饱和区。

---

### Q45：Multi-Head Attention 为什么有效？

```
MultiHead(Q,K,V) = Concat(head₁, ..., head_h) · W_O
  其中 head_i = Attention(Q·W_Qⁱ, K·W_Kⁱ, V·W_Vⁱ)
```

**为什么多头比单头好：**
1. **多视角学习**：每个 head 可以关注不同的模式（语法、语义、位置等）
2. **联合注意力**：多个子空间并行学习，表达能力更强
3. **分而治之**：每个 head 的维度 d_k = d_model / h，计算量不变

**实际观察：** 训练好的 Transformer 中不同 head 确实分化了——有的 head 主要关注句法关系（主语-谓语），有的关注位置距离，有的关注语义相似度。

### Q46：Transformer 的位置编码？绝对位置 vs 相对位置 vs RoPE？

| 编码方式 | 原理 | 代表模型 |
|----------|------|----------|
| **Sinusoidal (绝对位置)** | 正弦/余弦固定频率编码 | Transformer 原版 |
| **Learned (绝对位置)** | Embedding 层学习位置向量 | BERT、GPT-2 |
| **RoPE (旋转位置编码)** | 在 attention 计算中通过旋转矩阵编码位置 **相对关系** | LLaMA、GLM、Qwen |
| **ALiBi** | attention score 加位置偏置，不修改 embedding | BLOOM、MPT |
| **No Position (T5)** | 用 attention bias 编码相对位置 | T5 |

**RoPE 为什么主流：**
1. 本质是编码**相对位置**：两个 token 的 attention score 只取决于它们的距离
2. 有良好的**远程衰减**特性（相距越远，影响越小）
3. 支持上下文窗口**外推**（训练 8K 可推理到 32K）
4. 计算高效：只需要在 Q 和 K 上做旋转操作

**RoPE 的公式直觉：**
```
f(q, m) = q · (cos(mθ), sin(mθ))  按 2D 分组旋转
位置 m 和 n 的两个 token 的 attention score = q_m · k_n 会包含 (m-n) 的旋转差
```

### Q47：Transformer 的 Feed-Forward Network (FFN) 作用？

```
FFN(x) = W₂·(σ(W₁·x + b₁)) + b₂
```

- 通常 W₁ 升维（4× d_model），W₂ 降维回 d_model
- 激活函数：ReLU → GELU → SwiGLU（LLaMA 用）

**FFN 的作用：** Attention 层负责**信息的交互与聚合**（token 间 mixing），FFN 层负责**信息的变换与存储**（token 内处理）。有研究发现 FFN 中存储了大量的事实知识——每个神经元的激活模式与特定的概念/事实相关。

### Q48：Transformer 的 Encoder-Decoder vs Encoder-only vs Decoder-only？

| 架构 | 代表模型 | 特点 | 适用 |
|------|----------|------|------|
| **Encoder-Only** | BERT、RoBERTa | 双向注意力 | 理解任务（分类、NER、QA） |
| **Decoder-Only** | GPT、LLaMA、Qwen | 单向（因果）注意力 | 生成任务（对话、写作、代码） |
| **Encoder-Decoder** | T5、BART | 编码器双向 + 解码器单向 | 序列转换（翻译、摘要） |

**为什么 Decoder-Only 成为主流：**
1. 自回归 next token prediction 是最通用的预训练目标
2. 可以 zero-shot 做理解任务（但不如 BERT）
3. 架构简单，易于 scaling
4. 与人类使用场景匹配（对话就是自回归）

**面试加分：** 说 Decoder-Only 不能做理解任务是片面的。GPT-4 在几乎所有 NLU benchmark 上超越了 BERT——说明参数量足够大时，理解能力自然涌现。但在同等参数量下，BERT 的理解能力仍然优于 GPT。

### Q49：什么是 Causal Attention (因果注意力) / Masked Attention？

自回归模型要求 token 只能关注到它**左边**的 token，不能"看到未来"。

```
   I   love  eating  apples
I  1    0      0       0       ← "I" 只能看自己
love  1    1      0       0       ← "love" 能看 I 和 love
eating 1   1      1       0       ← "eating" 能看前三个
apples 1   1      1       1       ← "apples" 能看所有

0 = -∞ (softmax 后 ≈ 0)
1 = 允许关注
```

**实现：** 在 softmax 之前将未来位置的 attention score 设为 -∞（加上一个上三角 mask 矩阵，右上角全部为 -∞）。

### Q50：什么是 KV Cache 的显存优化？Multi-Query Attention (MQA) 和 Grouped-Query Attention (GQA)？

| 变体 | Key/Value head 数 | 显存节省 | 质量损失 | 代表模型 |
|------|-------------------|----------|----------|----------|
| **MHA (Multi-Head)** | = Query head 数 | 基准 | — | Transformer 原版 |
| **MQA (Multi-Query)** | 1 个 KV head | ~H 倍 | 微损失 | PaLM |
| **GQA (Grouped-Query)** | N 个 KV head (N<H) | ~H/N 倍 | 基本无损 | LLaMA-2-70B, LLaMA-3 |

**GQA 的 tradeoff：** Q 有 H 个 head 保持表达能力，K/V 分 N 组减少 KV Cache 大小。LLaMA-2-70B 用 GQA (KV=8, Q=64)，Cache 减到 1/8。

### Q51：什么是 RMSNorm？和 LayerNorm 的区别？

**RMSNorm：** 只做均方根归一化，去掉 LayerNorm 的均值中心化。

```
LayerNorm: y = (x - μ) / √(σ² + ε) × γ + β
RMSNorm:   y = x / √(mean(x²) + ε) × γ
```

**RMSNorm 的好处：**
- 计算量减少 ~10%（省了均值和方差的分别计算）
- LLM 中效果和 LayerNorm 接近
- LLaMA、Qwen 等现代模型都用 RMSNorm

### Q52：什么是 SwiGLU 激活函数？

SwiGLU = Swish × GLU (Gated Linear Unit)

```
SwiGLU(x) = Swish(W₁·x) ⊗ (W₂·x)    (⊗ 是逐元素乘)
Swish(x) = x · sigmoid(β·x)
```

**为什么用 SwiGLU：**
- GELU 和 Swish 在 LLM 中效果优于 ReLU
- SwiGLU 比单纯 Swish 多了 gating 机制（类似 LSTM 的门控）
- 多一个 W 矩阵，参数量增加（LLaMA 中用 `8/3 d_model → 8/3 d_model` 替代了原来的 `4× d_model`）

| 激活函数 | 代表模型 |
|----------|----------|
| ReLU | Transformer 原版、BERT |
| GELU | GPT-3、BERT(现代版) |
| SwiGLU | LLaMA、Qwen、Mistral、PaLM |

### Q53：Pre-LayerNorm vs Post-LayerNorm？为什么 Pre-LN 更稳定？

**Post-LN（原版 Transformer）：**
```
output = LayerNorm(x + Sublayer(x))
```

**Pre-LN（现代 LLM）：**
```
output = x + Sublayer(LayerNorm(x))
```

**Pre-LN 更稳定的原因：**
- Pre-LN 把 LayerNorm 放在子层之前，梯度可以直接绕过子层传播（捷径更干净）
- Post-LN 在残差连接之后做 Norm，深层的激活值范围大，容易不稳定
- Pre-LN 允许更高的学习率，训练更稳定

**代价：** Pre-LN 的最终输出没有 normalize（因为 Norm 在残差块内部），通常最后加一层 Final LN。整体效果 Pre-LN > Post-LN，所以现代 LLM 全部用 Pre-LN。

### Q54：什么是 FlashAttention 的改进版本？FlashAttention-2 和 FlashAttention-3？

**FlashAttention (2022):**
- 分块计算 + HBM ↔ SRAM 融合
- A100 利用率 ~50%

**FlashAttention-2 (2023):**
- 少 split 和非 matmul 操作
- 更好的线程调度（1 个 block 对应 1 个 warp）
- A100 利用率 ~70%

**FlashAttention-3 (2024):**
- 利用 Hopper 架构的 Tensor Core + FP8
- 异步处理 overlap 计算和数据传输
- H100 利用率 ~75%

**使用建议：** FlashAttention-2 已经是现代 LLM 训练和推理的事实标配。大部分框架（vLLM、PyTorch 2.x 等）默认集成。

## 七、场景设计题

### Q55：如果让你训练一个领域特定的小模型（如法律咨询模型），怎么做？

**方案：**

1. **基座选择**：选一个好的开源基座（如 Qwen-7B、LLaMA-3-8B），不要从零训练
2. **数据准备**：收集该领域的数据（裁判文书、法律法规），清洗→去重→质量筛选
3. **Continue Pre-training**：在领域数据上继续预训练（注入领域知识）
4. **SFT**：用 (用户问题, 律师回答) 的指令数据进行监督微调
5. **可选 RLHF/DPO**：如果有偏好数据，做对齐提升质量
6. **RAG 增强**：接入法规数据库做检索增强（最关键的一步——法律场景绝对不能瞎编）

**关键考量：**
- 数据质量 > 数量：1000 条高质量法律问答 > 100 万条爬虫数据
- 领域 continue pretrain 需要大量数据（通常 50B+ token），量小不如直接 SFT
- 法律场景中 RAG 是必须的——模型不可能记住所有法条，而且法条会更新

---

### Q56：一个对话场景下，用户反馈延迟很高，怎么排查？

**排查路径：**

1. **看首 token 延迟 (TTFT)** → 高说明 prefill 慢
   - 检查 prompt 是否过长？→ 需要上下文压缩
   - FlashAttention 是否启用？→ 未启用则开启
   - prompt caching 是否生效？→ 相同 prefix 可复用

2. **看生成速度 (TPOT)** → 高说明 decode 慢
   - batch size 是否太小？→ 增大 batch 提升吞吐（但会提高首 token 延迟）
   - KV Cache 是否溢出？→ 溢出后重新计算更慢
   - 模型太大不适合当前 GPU？→ 考虑量化或换小模型

3. **检查网络**：API 调用耗时？数据量过大？
4. **检查模型**：采样参数是否导致生成长？max_tokens 设高了？

**最快落地的优化：** 开启 vLLM 的 continuous batching → 吞吐提升 2~4x。

---

### Q57：如果模型在某个特定类别上表现很差（如总是把"退款"识别为"咨询"），怎么改进？

**诊断：** 先确定是数据问题还是模型问题
- 该类别在训练集中占比多少？→ 数据不平衡？
- 同类错误是否集中在某种模式？→ 特征混淆？
- 少量样本上做 few-shot 测试？→ 模型能力本身够不够？

**改进方案（按优先级）：**

1. **补数据**（最高 ROI）：收集更多该类别样本，特别是边界样本
2. **调阈值**：召回优先则降低类别阈值，Precision 优先则提高
3. **重采样**：训练时 oversample 该类
4. **Prompt 增强**：System Prompt 中强调该类别
5. **模型升级**：如果以上效果有限，说明模型在该类别上能力不足，考虑用更大的模型

---

### Q58：项目中有条 SQL 链路人月消耗 1000 元，老板让你降低成本到 500 元，怎么做？

**降低成本的三板斧（按实施难度排序）：**

1. **减少每次调用的 token 数**（最快见效）：
   - 压缩 prompt：精简 System Prompt、移除不必要的示例
   - Schema 只注入相关表（不是全部 7 张）
   - 缓存常见查询的 SQL 结果（Redis TTL=1h）

2. **换更便宜的模型**：
   - 核心推理从 Qwen 切到 DeepSeek（~5x 成本差）
   - 简单查询用更小模型（如 SQL 生成用 Qwen-7B 而不是 72B）

3. **减少调用次数**：
   - SQL 自修复只有第一次错了才触发（大部分情况一次过）
   - 语义缓存：相似问题直接返回（预期省 15%）
   - 预聚合：非实时查询直接查预聚合表而不是走 NL2SQL

**预期效果：** 三者叠加，1000 → 400~500 元是可行的。

---

### Q59：多个 GPU 做分布式训练时，Loss 震荡或 NaN 怎么办？

**排查步骤：**

1. **检查是否单卡的问题**：先在一张卡上跑小 batch，看是否稳定
2. **确认分布式设置正确**：
   - 学习率是否按卡数调整？Linear Scaling Rule：lr × √(n_gpus)
   - Global batch size 是否过大？过大导致收敛不稳定
   - 梯度和 loss 是否在所有卡上同步？（`all_reduce` 正确配置）
3. **检查数值稳定性**：
   - 开启 `torch.set_autocast`（自动混合精度）
   - 梯度裁剪（`max_grad_norm=1.0`）
   - 检查 loss 的 NaN 来源（哪个层的梯度爆炸？）
4. **常见 GPU 间问题**：
   - 数据加载不一致（不同卡读到不同分布的数据）
   - 随机种子没设（不同卡初始化不同）
   - 通信延迟导致梯度不同步

### Q60：从零设计一个模型评估平台/框架，需要哪些核心能力？

**核心模块：**

| 能力 | 说明 |
|------|------|
| **测试集管理** | 上传、版本管理、标签 |
| **评估任务编排** | 选择模型 + 数据集 + 评估指标 |
| **指标计算** | Accuracy / F1 / ROUGE / BLEU / GPT-4 打分 |
| **对比分析** | 多模型同场景的对比看板 |
| **Bad Case 管理** | 标记、分类、归因分析 |
| **回归测试** | 每次模型更新自动跑历史 bad case |
| **评估报告** | 自动生成可分享的报告 |

**设计原则：**
- **自动化**：CI/CD 集成，模型上线前自动评估
- **可复现**：评估配置（数据集版本、指标参数、模型版本）可导出
- **可扩展**：自定义指标接口、自定义数据集格式

**面试加分：** 评估平台最有价值的能力是 **Bad Case 管理 + 回归测试**——单纯跑指标只能知道"好不好"，bad case 分析能告诉你"哪里不好"和"怎么改进"。
