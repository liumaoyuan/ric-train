## Phase 1：系统管理（RBAC）+ 聊天助手

### 1.1 项目初始化

**文件：** `CateringAiSystem/__init__.py`、`CateringAiSystem/main.py`

- 创建 `CateringAiSystem` 包结构
- 主入口加载所有路由、注册数据库连接、启动调度器
- 参考 `Base/main.py` 的模式

### 1.2 认证与鉴权中间件

**文件：** `CateringAiSystem/Middleware/authMiddleware.py`、`CateringAiSystem/Utils/authUtils.py`

- **JWT 认证**：使用 `PyJWT` 签发和验证 Token
  - 登录成功返回 access_token（短期，2 小时）+ refresh_token（长期，7 天）
  - Token 中包含 user_id、username、roles 信息
- **依赖注入函数**：`get_current_user()` 供路由直接使用
- **权限校验**：函数式 `require_permission(code)` 按模块校验（模块级可见性，不细化到按钮）
- **复用 Base**：密码使用 `passlib` + bcrypt 加密

### 1.3 系统管理数据模型

**文件：** `CateringAiSystem/Models/sysModels.py`

5 张表，继承 `BaseModuleDBModel`，存储在 `ric_ai_base` 数据库：

| 表名 | 类名 | 说明 |
|------|------|------|
| `sys_user` | `SysUser` | 系统用户（含 password_hash） |
| `sys_role` | `SysRole` | 角色定义 |
| `sys_menu` | `SysMenu` | 菜单树（目录/菜单两级，不含按钮级） |
| `sys_role_menu` | `SysRoleMenu` | 角色-菜单多对多 |
| `sys_user_role` | `SysUserRole` | 用户-角色多对多 |

建表 SQL 直接在模型中声明 `create_table_sql`，利用 Base 框架自动建表。

### 1.4 认证 API

**文件：** `CateringAiSystem/Api/authApi.py`、`CateringAiSystem/Service/authService.py`

| 接口 | 说明 |
|------|------|
| `POST /api/v1/auth/login` | 用户名+密码登录，返回 JWT Token |
| `POST /api/v1/auth/logout` | 登出 |
| `GET /api/v1/auth/userinfo` | 获取当前用户信息、角色、权限列表 |

**登录流程：**
1. 根据 username 查询 `SysUser`

4. 生成 JWT Token（payload 含 user_id, username, roles, permissions）
5. 返回 Token + 用户信息

### 1.6 聊天助手（LangChain Agent）

**文件：** `CateringAiSystem/Api/chatApi.py`、`CateringAiSystem/Service/chatService.py`
**新增：** `CateringAiSystem/Agent/`

聊天助手基于 **LangChain create_agent() API** 实现，按角色缓存全局单例，通过 `contextvars` 做会话隔离。

#### 1.6.1 Agent 架构

```
用户输入 → POST /api/v1/chat/ask
  → chatService.ask_stream()
      → AgentMemory.get_or_create_session()  # 会话管理
      → get_agent_for_role()                 # 获取/创建角色 Agent 全局单例
      → AgentMemory.build_memory_messages()  # 加载记忆上下文
      → agent.astream()                      # LangGraph Agent 流式执行
          ├─ ChatMemoryMiddleware            # 超阈值自动摘要压缩（15轮/5000字符）
          ├─ LLM（通义千问 via ChatOpenAI）   # 模型推理
          └─ @tool 工具调用                   # 按需选择执行
      → 逐 token yield SSE 事件
      → push_to_redis() + save_conversation() # 记忆持久化
```

#### 1.6.2 Agent 工具集

**文件：** `CateringAiSystem/Agent/tools.py`

四个 `@tool` 装饰器定义的函数工具：

| 工具名 | 触发场景 | 实现要点 |
|--------|---------|---------|
| `knowledge_search` | 公司制度、菜品知识、SOP 等知识类问题 | 通义千问 LLM 基于知识库回答（后续接入真实 RAG） |
| `data_query` | 营业额、订单量、菜品排行等数据类问题 | **真实 NL2SQL**：Schema 注入 → SQL 生成 → 语法校验 → 安全过滤 → 执行查询 |
| `web_search` | 行业新闻、竞品动态等需实时信息的问题 | 通义千问内置联网搜索（`enable_search=True`） |
| `general_chat` | 闲聊、问候等无工具匹配时的兜底回复 | 直接调用通义千问对话 |

#### 1.6.3 NL2SQL 真实执行

**文件：** `CateringAiSystem/Utils/sql_guard.py`

```python
# data_query 工具核心逻辑
async def data_query(question: str) -> str:
    # 1. Schema 注入：传递表结构 + 字段说明 + 示例数据
    schema_context = """
    表 daily_summary:
      store_id(门店ID), summary_date(日期), total_revenue(总营业额),
      total_orders(订单数), avg_price(客单价)
    表 store: store_id, store_name(门店名), province(省), city(市)
    ...
    """
    # 2. LLM 生成 SQL
    sql = await llm.invoke(build_nl2sql_prompt(question, schema_context))
    
    # 3. 安全校验
    sql_guard.validate(sql)  # 检查只读、表名白名单、LIMIT 上限
    
    # 4. 执行查询
    result = repository.execute(sql)
    
    # 5. LLM 总结回答
    return await llm.invoke(build_summary_prompt(question, result))
```

**安全策略（`sql_guard.py`）：**
- 数据库连接使用**只读事务**，禁止 INSERT/UPDATE/DELETE
- SQL 表名和字段名做白名单校验，只允许预注册的业务表
- 自动加 `LIMIT 200` 上限，防止查询结果过大
- 不支持子查询、JOIN 以外的复杂语法（对 LLM 生成的 SQL 做严格限制）
- SQL 执行异常时捕获错误信息发给 LLM 自行修正，最多重试 2 次

#### 1.6.4 对话记忆管理

**文件：** `CateringAiSystem/Agent/memory.py`、`CateringAiSystem/Agent/middleWare.py`

**双层存储架构：**

| 层级 | 存储 | 用途 | TTL |
|------|------|------|-----|
| 短期记忆 | Redis（`agent:memory:{session_id}`） | 最近对话消息列表 | 24h |
| 摘要 | Redis（`agent:summary:{session_id}`） | AI 压缩的会话摘要 | 7d |
| 持久化 | MySQL（`base_llm_conversation`） | 全量对话记录 | 永久 |
| 会话元数据 | MySQL（`base_llm_session`） | 会话信息与摘要 | 永久 |
| 向量 | Milvus | 向量检索 | 永久 |

**记忆加载优先级：** Redis 消息列表 + Redis 摘要 → Redis 空则从 MySQL 回退加载并同步 Redis。组合为 `[摘要SystemMessage] + [历史对话HumanMessage/AIMessage]` 注入 Agent。

**记忆压缩（ChatMemoryMiddleware）：** 消息超过 15 轮或 5000 字符时触发 LLM 智能摘要，保留最近 5 轮完整消息，摘要同步更新 Redis + MySQL。

#### 1.6.5 流式响应

- **后端**：FastAPI `StreamingResponse(content_type="text/event-stream")`，Agent 的 `astream()` 逐 token 产出
- **SSE 事件格式**：`data: {"type":"start"|"content"|"done"|"error", "content":"...", "session_id":"..."}\n\n`
- **前端**：原生 `fetch` + `ReadableStream.getReader()` 读取流，支持 `AbortController` 取消请求

#### 1.6.7 权限隔离

#### 1.6.8 全局单例与上下文隔离

```python
_role_agents: dict = {}  # key="admin:employee", value=Agent 实例

async def get_agent_for_role(role_codes):
    key = ":".join(sorted(role_codes))
    if key not in _role_agents:
        _role_agents[key] = build(role_codes)
    return _role_agents[key]
```

通过 `contextvars.ContextVar`（`_session_id_var` / `_user_id_var`）在中间件中动态获取当前会话上下文，实现单例 Agent 的多会话隔离。

### 2.3 营业数据分析服务

**文件：** `CateringAiSystem/Service/analysisService.py`、`CateringAiSystem/Api/analysisApi.py`

#### 2.3.1 分层分析策略

```
原始数据（MySQL） → SQL 预聚合 → 指标计算 → LLM 分析 → 报告输出
                              ↑                       ↑
                        daily_summary 表        prompt 模板 + 指标数据
```

1. **SQL 预聚合**：从 `daily_summary` 表聚合（每店每日一条），不接触原始明细
2. **指标计算**：Python 层完成同比环比，只传入结构化数值（<500 tokens）
3. **LLM 分析**：生成"数据概览 → 关键发现 → 改进建议"三段式报告
4. **分层下钻**：报告检测异常时，按需查询日维度明细

预聚合结果缓存至 Redis（TTL=1 小时），避免重复计算。

### 2.4 风评分析

**文件：** `CateringAiSystem/Service/reviewService.py`、`CateringAiSystem/Api/reviewApi.py`

#### 2.4.1 功能列表

| 功能 | 用户 | 说明 | 优先级 |
|------|------|------|--------|
| 评论查询与筛选 | 总部、加盟商 | 按门店/平台/评分/时间筛选模拟评论数据 | P0 |

#### 3.3.2 错误恢复与降级策略

**文件：** `CateringAiSystem/Utils/retry.py`

```python
class LLMRetryHandler:
    """多模型降级 + 指数退避重试"""
    
    MODELS = [
        ("qwen", qwen_llm, 3),      # (name, instance, max_retries)
        ("deepseek", deepseek_llm, 2),
    ]
    
    async def safe_call(self, prompt: str) -> str:
        for model_name, model, max_retries in self.MODELS:
            for attempt in range(max_retries):
                try:
                    return await model.ainvoke(prompt)
                except RateLimitError:
                    await asyncio.sleep(2 ** attempt)  # 退避
                except TimeoutError:
                    await asyncio.sleep(1)
        return FALLBACK_RESPONSE  # 全部失败兜底
```

### 4.4 流式聊天前端实现

```javascript
// api/chat.js — SSE 流式请求
export function askQuestionStream(data, onMessage, onError, onDone) {
  const controller = new AbortController();
  fetch('/api/v1/chat/ask', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json', ... },
    body: JSON.stringify(data),
    signal: controller.signal,
  }).then(async response => {
    const reader = response.body.getReader();
    const decoder = new TextDecoder();
    while (true) {
      const { done, value } = await reader.read();
      if (done) break;
      const text = decoder.decode(value);
      // 解析 SSE: data: {"type":"content","content":"..."}\n\n
      for (const line of text.split('\n')) {
        if (line.startsWith('data: ')) {
          const parsed = JSON.parse(line.slice(6));
          if (parsed.type === 'content') onMessage(parsed);
          else if (parsed.type === 'done') onDone();
          else if (parsed.type === 'error') onError(parsed);
        }
      }
    }
  }).catch(err => {
    if (err.name !== 'AbortError') onError(err);
  });
  return () => controller.abort();  // 取消请求
}
```
