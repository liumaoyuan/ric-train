### 1.1 项目初始化

### 1.2 认证与鉴权中间件

**文件：** `CateringAiSystem/Middleware/authMiddleware.py`、`CateringAiSystem/Utils/authUtils.py`

- **JWT 认证**：使用 `PyJWT` 签发和验证 Token
  - 登录成功返回 access_token（短期，2小时）+ refresh_token（长期，7天）
  - Token 中包含 user_id、username、roles 信息
- **依赖注入函数**：`get_current_user()` 供路由直接使用
- **权限中间件**：`require_permission(code)` 装饰器用于按钮级鉴权
- **复用 Base**：密码使用 `passlib` + bcrypt 加密

### 1.8 聊天助手（LangChain Agent）

**文件：** `CateringAiSystem/Api/chatApi.py`、`CateringAiSystem/Service/chatService.py`
**新增：** `CateringAiSystem/Agent/`、`CateringAiSystem/Agent/tools/`

聊天助手基于 **LangChain Agent** 架构实现，替代原有的简单意图路由。Agent 根据用户问题动态选择工具，支持多轮对话中的工具编排。

#### 1.8.1 Agent 架构

```
用户输入 → ChatParams（问题/会话/流式等参数）
  → Base 层：文本审核（AiService.auditing_text）
  → Base 层：问题改写（AiService.rewrite_question）
  → Base 层：会话记忆加载（MemoryV1Service）
  → LangChain Agent 执行器
      ├─ 思考（ReAct 推理）
      ├─ 选择工具 → 执行 → 观察结果
      └─ 循环直到生成最终答案
  → 持久化对话记录（persist_conversation 装饰器）
```

#### 1.8.2 Agent 工具集

每个工具封装为一个 LangChain `Tool`，注册到 Agent 的 tool 列表中：

| 工具名 | 类/函数 | 说明 | 用户范围 |
|--------|---------|------|----------|
| `knowledge_search` | `KnowledgeSearchTool` | RAG 知识库检索，传入问题返回相关文档片段 | 总部/加盟商（按权限范围） |
| `data_query` | `DataQueryTool` | 门店数据查询，自然语言转 SQL 或查预定义报表 | 总部/加盟商（按数据范围） |
| `web_search` | `WebSearchTool` | 联网搜索，调用 Qwen `enable_search=True` | 仅总部 |
| `general_chat` | `GeneralChatTool` | 通用闲聊，无工具可匹配时的兜底回复 | 全部 |

#### 1.8.5 LangChain 集成方案

```
Base.Ai.llms.qwenLlm (QwenLlm)
    ↓ 适配
LangChain LLM 包装器 (QwenLangChainLLM)
    ↓
LangChain Agent Executor
    ↓ 调用
各 Tool（继承 BaseTool）
```

**Qwen 适配 LangChain：**

```python
from langchain.llms.base import LLM
from Base.Ai.llms.qwenLlm import QwenLlm

class QwenLangChainLLM(LLM):
    """将 Base 的 QwenLlm 适配为 LangChain LLM 接口"""
    qwen: QwenLlm = None
    
    def _call(self, prompt: str, **kwargs) -> str:
        return self.qwen.invoke(prompt=prompt)
    
    @property
    def _llm_type(self) -> str:
        return "qwen"
```

#### 1.8.7 权限隔离

- **老板**：注册全部 4 个工具，可查询全部门店

- **加盟商**：仅注册 `knowledge_search` + `data_query` + `general_chat`（无 web_search），数据范围仅本门店

权限信息在 Agent 初始化时注入，通过 Prompt 约束和工具内部过滤双重保障。

#### 3.2.1 知识库数据模型

**文件：** `CateringAiSystem/Models/knowledgeModels.py`

**`knowledge_document` 表（文档记录）：**


**`knowledge_chunk` 表（文档分块记录，可选——也可通过 Milvus scalar 字段管理）：**

```python
class KnowledgeChunk(BaseModuleDBModel):
    """知识库文档分块记录"""
    table_alias = "knowledge_chunk"
    # 字段：
    #   id, doc_id, chunk_index, chunk_content(文本内容),
    #   vector_id(Milvus 中的 ID), token_count,
    #   permission_scope(继承自文档，用于 Milvus 过滤),
    #   chunk_strategy(fixed/paragraph/recursive/qa_pair),
    #   question(问答对模式下的问题，非问答对模式为空),
    #   is_selected(预览时用户是否勾选，默认1=勾选)
```

**Milvus Collection 设计：**

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | INT64 | 主键（自增） |
| `vector` | FLOAT_VECTOR(768) | Embedding 向量（Qwen text-embedding-v3） |
| `chunk_text` | VARCHAR(65535) | 分块文本内容（问答对模式下为 answer） |
| `doc_id` | INT64 | 所属文档 ID |
| `category` | VARCHAR(64) | 文档分类 |
| `permission_scope` | VARCHAR(32) | 权限范围: `all` / `employee_only` / `franchisee_only` |
| `chunk_index` | INT64 | 分块序号 |
| `chunk_strategy` | VARCHAR(32) | 分块策略: `fixed` / `paragraph` / `recursive` / `qa_pair` |
| `question` | VARCHAR(1024) | 问答对模式下的问题（用于检索匹配），非问答对模式为空 |

> 问答对模式下：`question` 作为辅助检索字段，`chunk_text` 存储回答内容。检索时优先匹配 `question` + `chunk_text`，返回时展示 `Q: question / A: chunk_text` 格式。

> 权限范围存储在 Milvus 的 scalar 字段中，检索时通过 `expr` 参数过滤，实现向量检索与权限控制的结合。

#### 3.2.2 文档上传与处理流程

```
上传请求 → 文件校验（类型/大小/病毒扫描省略）
  → 存入 MinIO（原始文件备份）
  → 创建 KnowledgeDocument 记录（status=0 处理中）
  → 异步执行文本提取：
      ├─ PDF → pdfUtils（Base.RicUtils.pdfUtils）
      ├─ Word → docUtils（Base.RicUtils.docUtils）
      ├─ TXT/MD → 直接读取
      └─ 失败 → status=2，记录 error_msg
  → 提取完成后 status=3（待分块）
  → 前端发起 GET /preview 获取分块预览（见下方预览流程）

分块预览流程（调用 POST /knowledge/{id}/preview）：
  ├─ 根据文档的 chunk_strategy 配置执行分块
  ├─ 分块策略 A/B/C/D 任选其一（上传时指定，预览时可临时切换）
  ├─ 返回分块结果列表（不写入 Milvus）
  └─ 前端渲染预览界面，用户逐块勾选

确认向量化流程（调用 POST /knowledge/{id}/vectorize）：
  ├─ 接收前端提交的勾选结果（selected_chunk_indexes）
  ├─ 仅对勾选的分块执行 Embedding 向量化
  ├─ 批量插入 Milvus
  ├─ 创建/更新 KnowledgeChunk 记录
  └─ KnowledgeDocument.status = 1（已就绪）
```

#### 3.2.3 支持的文档格式

| 格式 | 解析方案 | 限制 |
|------|----------|------|
| PDF | `Base.RicUtils.pdfUtils`（文字型 PDF） | 扫描件需 OCR（暂不支持） |
| DOCX | `Base.RicUtils.docUtils`（python-docx） | 纯文本段落提取 |
| DOC | 需转换（通过 soffice/libreoffice 转 docx） | 可选 |
| TXT | 直接读取 UTF-8 | 无 |
| MD | 直接读取 | 保留标题层级用于分块 |

```python
def search_knowledge(query: str, user_role: str, user_permissions: list, top_k: int = 5):

    elif user_role == 'employee':
        scope_filter = 'permission_scope in ["all", "employee_only"]'
    elif user_role == 'franchisee':
        scope_filter = 'permission_scope in ["all", "franchisee_only"]'
    
    # 向量检索 + 权限过滤
    results = milvus_collection.search(
        data=[embedding],
        anns_field="vector",
        expr=scope_filter,  # Milvus scalar 过滤

    return results
```

#### 3.3.1 菜品图生成

图片生成直接调用 Qwen 系列模型的文生图能力（通义万相）：

```
描述文本 → QwenLlm（文生图接口）→ 图片 → MinIO 存储 → 返回 URL
```

#### 3.3.2 短视频生成方案概述

提供 **两种生成方案**，用户在发起生成时选择（通过 `generation_mode` 参数）：

| 方案 | 模式 | 原理 | 成本 | 质量 |
|------|------|------|------|------|
| **方案A：图片合成** | `image_compose` | LLM剧本 + 文生图 + TTS + FFmpeg 合成 | 0.02~0.8元/条 | 图片幻灯片+转场 |
| **方案B：AI视频模型** | `video_model` | LLM剧本 + 通义万相视频生成模型直出 | 1.5~15元/条 | 真实动态画面 |

两种方案共享分镜剧本生成、模板系统、素材存储，仅在"画面生成"环节分流。

```
用户输入（菜品 + 模板）
  → LLM 生成分镜脚本（共用）
  → 选择方案：
      ├─ 方案A：文生图 → FFmpeg合成 → TTS旁白
      └─ 方案B：Wan2.6 文生视频 / Wan2.2 Flash 图生视频
  → 存入 MinIO → 返回 URL
```

#### 3.3.7 Python 视频合成服务

```python
class VideoComposer:
    """视频合成引擎"""
    
    def __init__(self):
        self.ffmpeg_path = settings.ffmpeg.path or "ffmpeg"
    
    def compose(self, scenes: list, narration_audio: str, output_path: str) -> str:
        """
        合成短视频
        :param scenes: 分镜列表 [{image_path, duration, transition}]
        :param narration_audio: 旁白音频路径
        :param output_path: 输出视频路径
        :return: 输出视频路径
        """
        # 1. 为每个分镜生成静帧视频片段
        segment_files = []
        for i, scene in enumerate(scenes):
            seg = self._create_segment(scene, i)
            segment_files.append(seg)
        
        # 2. 拼接所有片段
        concat_file = self._concat_segments(segment_files)
        
        # 3. 叠加音频
        final = self._add_audio(concat_file, narration_audio, output_path)
        
        # 4. 清理临时文件
        self._cleanup(segment_files + [concat_file])
        
        return final
    
    def _create_segment(self, scene: dict, index: int) -> str:
        """将单张图片转为指定时长的静帧视频"""
        cmd = (
            f"{self.ffmpeg_path} -loop 1 -i {scene['image_path']} "
            f"-c:v libx264 -t {scene['duration_sec']} "
            f"-pix_fmt yuv420p -vf 'scale=1920:1080:force_original_aspect_ratio=decrease,"
            f"pad=1920:1080:(ow-iw)/2:(oh-ih)/2' "
            f"/tmp/segment_{index}.mp4 -y"
        )
        subprocess.run(cmd, shell=True, check=True)
        return f"/tmp/segment_{index}.mp4"
    
    def _concat_segments(self, segments: list) -> str:
        """拼接多个视频片段"""
        filelist = "/tmp/filelist.txt"
        with open(filelist, 'w') as f:
            for seg in segments:
                f.write(f"file '{seg}'\n")
        output = "/tmp/concat.mp4"
        cmd = f"{self.ffmpeg_path} -f concat -safe 0 -i {filelist} -c copy {output} -y"
        subprocess.run(cmd, shell=True, check=True)
        return output
```

### 预置菜单初始化脚本

系统启动时通过 `init_sys_menu.py` 脚本将上述菜单树写入 `sys_menu` 表，同时预置三员角色并分配对应菜单权限：

- **admin（老板）**：全部菜单
- **employee（普通员工）**：除系统管理外的全部菜单（需授权项默认关闭）
- **franchisee（加盟商）**：数据中心（仅本门店）+ 风评（仅本门店）+ 知识库 + 培训 + 聊天助手

### JWT 鉴权流程

```
请求 → authMiddleware（检查 Authorization header）
  → 解析 JWT Token → 获取 user_id/roles/permissions
  → 注入到 request.state.current_user
  → 路由处理（通过 require_permission 装饰器校验按钮级权限）
```

### RBAC 权限校验

```python
# 装饰器方式
@router.post("/sys/user")
@require_permission("sys:user:add")
def create_user(...): ...

# 方式2：依赖注入
def get_current_user() -> dict: ...
```

### 定时任务自实现

**不使用** `Base/Service/scheduler/auto_register.py`（静态代码扫描），
而是自实现完整的动态调度引擎：

- **核心**：APScheduler `BackgroundScheduler`
- **存储**：MySQL 持久化（基于 APScheduler 的 `SQLAlchemyJobStore`）
- **加载**：启动时从 `sys_task` 表读取所有运行中的任务
- **管理**：API 操作实时同步到调度器

优势：支持运行时动态增删改任务，无需重启服务，有完整执行日志。
