## 1. 项目概述

### 1.1 项目背景

本项目旨在为连锁中式快餐企业构建一套智能化的 AI 辅助管理系统，覆盖总部运营管理及加盟商日常经营的各个环节。通过引入大语言模型（LLM）、RAG（检索增强生成）、向量数据库、知识图谱等技术，提升企业在数据分析、员工培训、客户服务、门店运营等方面的效率与智能化水平。

### 1.2 项目目标

- 为总部提供多维度营业数据分析与行业洞察能力
- 为加盟商提供门店级的智能运营工具（智能备菜、风评分析、聊天助手）
- 构建企业知识库，实现公司制度、菜品专业知识的高效检索与问答
- 通过 AI 能力降本增效，覆盖菜品素材生成、外卖运营、客户沟通等场景

### 1.3 适用范围

适用于连锁中式快餐企业的总部管理部门及所有加盟门店。

## 2. 用户角色与权限体系

权限体系采用 **RBAC（基于角色的访问控制）** 模型，支持角色的动态扩展。系统预置三个基础角色，后续可根据业务需求新增自定义角色并分配权限。

### 2.1 权限模型

```
用户 → 角色（可多角色） → 权限集合
```

- 角色与权限分离：一个角色可包含多个权限项，一个用户可拥有多个角色
- 权限粒度：功能模块级 + 数据级（如某门店范围）
- 动态扩展：通过管理后台新建角色、配置权限，无需修改代码

### 2.2 内部用户 — 老板

拥有系统最高权限，可访问所有功能模块的全局数据。

**核心职责：**
- 全局营业数据分析与决策
- 行业趋势研究与竞争分析
- 新门店选址评估
- 品牌风评全局监控
- AI 菜品图与视频素材生产
- 外卖运营策略制定与优化
- 加盟商管理
- 员工账号管理与权限分配

### 2.3 内部用户 — 普通员工

拥有部分运营模块的使用权限，受限于老板分配的数据范围。

**核心职责：**
- 协助营业数据整理与报表生成
- 行业信息收集与报告整理
- 培训资料维护
- 素材制作与处理
- 日常运营辅助工作

### 2.4 加盟商（Franchisee）

加盟商用户可访问**本门店维度**的数据与功能，获得日常经营所需的 AI 辅助能力。

**核心职责：**
- 本门店营业数据分析
- 本门店风评监控与复盘
- 智能备菜与采购管理
- 内部聊天助手（公司制度查询、菜品知识问答）
- 外卖运营辅助

## 3. 技术架构

### 3.1 整体架构

| 层级 | 技术选型 | 说明 |
|------|----------|------|
| 后端框架 | FastAPI | 高性能异步 Python Web 框架 |
| 前端框架 | Vue 3 | 现代前端 SPA 框架 |
| LLM 框架 | LangChain | 大语言模型应用编排框架 |
| 关系数据库 | MySQL | 业务数据持久化存储 |
| 向量数据库 | Milvus（远程） | 知识库向量检索与语义搜索 |
| 缓存 | Redis | 会话缓存、API 缓存、数据缓存 |
| 对象存储 | MinIO | 文件、图片、音视频素材存储 |
| 图数据库 | Neo4j | 知识图谱存储与查询 |
| LLM 服务 | Qwen（通义千问）/ DeepSeek | 大语言模型推理服务 |

```
└─────────────────────┬───────────────────────────┘
                      │
┌─────────────────────▼───────────────────────────┐
│               业务服务层（Service）                 │
│ AI 服务  │  数据分析  │  知识库  │  培训  │  风评   │
│ 备菜引擎 │  外卖运营  │  素材生成 │  选址    │        │
└─────────────────────┬───────────────────────────┘
                      │
┌─────────────────────▼───────────────────────────┐
│            基础设施 / 中间件层                     │
│  MySQL  │  Milvus  │  Redis  │  MinIO  │  Neo4j  │
└─────────────────────────────────────────────────┘
```

### 3.3 现有基础模块说明

项目已有完善的 `Base` 基础模块，包含以下核心能力：

- **Base.Ai**：统一的 LLM 抽象层，支持 Qwen（通义千问）和 DeepSeek 模型，提供同步/异步、流式/非流式调用、OCR/ASR/Embedding 等功能
- **Base.Repository**：数据库仓库层，支持 MySQL、Milvus、PostgreSQL、SQLite 等多种数据库
- **Base.Client**：各类客户端封装（Redis、MinIO、NEO4J、TTS、ASR 等）
- **Base.Models**：数据模型层，覆盖对话、会话、关键词等业务模型
- **Base.RicUtils**：工具类库（日期、文件、Excel、PDF、HTTP 等）
- **Base.Service**：基础业务服务（AI 对话、会话管理、记忆服务、定时任务等）

## 4. 功能模块详细需求

### 4.1 营业数据分析

#### 4.1.1 概述

利用 AI 对门店经营数据进行多维度分析，自动生成分析报告，辅助经营决策。门店营业数据使用模拟数据，通过数据初始化脚本批量生成，存储在 MySQL。

#### 4.1.2 数据说明

门店营业数据（订单明细、营业汇总等）均为**模拟生成数据**，不对接真实收银系统。通过脚本按以下规则生成：
- 设定门店基数，叠加随机波动生成每日营收
- 加入季节趋势、节假日效应等模拟真实业务形态
- 数据量级：每店每日数十至数百条订单记录
- 数据周期：1 年（默认 2025 年全年）
- 支持按门店、日期范围重新生成或增量补充

#### 4.1.3 功能列表

| 功能 | 用户 | 描述 | 优先级 |
|------|------|------|--------|
| 门店维度分析 | 总部、加盟商 | 按门店查看营业数据，支持年度/月度筛选 | P0 |
| 总体维度分析 | 总部 | 查看所有门店汇总数据，支持年度/月度筛选 | P0 |
| 同比环比分析 | 总部、加盟商 | 支持与去年同期、上月的数据对比 | P1 |
| 趋势预测 | 总部 | 基于历史数据预测未来营收趋势 | P2 |
| AI 分析报告 | 总部、加盟商 | 基于数据自动生成自然语言分析报告，包含亮点、问题、建议 | P0 |
| 数据可视化 | 总部、加盟商 | 营收、客单价、翻台率等关键指标的图表展示 | P1 |

#### 4.1.3 数据维度

- 营收总额
- 订单数量
- 客单价
- 翻台率
- 各品类销量及占比
- 高峰时段分析
- 外卖 vs 堂食占比

#### 4.1.4 AI 分析报告要求

- 自动识别数据中的异常波动并给出原因分析
- 结合天气、节假日等外部因素提供经营建议
- 报告格式支持结构化的"数据概览 → 关键发现 → 改进建议"

### 4.2 行业分析

#### 4.2.1 概述

总部通过联网搜索获取国内外餐饮行业最新数据与趋势，自动生成行业分析报告。

#### 4.2.2 功能列表

| 功能 | 用户 | 描述 | 优先级 |
|------|------|------|--------|
| 联网搜索 | 总部 | 自动搜索国内外餐饮行业最新资讯、数据报告 | P0 |
| 竞品动态监控 | 总部 | 跟踪主要竞争对手的新品、活动、扩张动态 | P1 |
| 行业报告生成 | 总部 | 基于搜索结果自动生成结构化的行业分析报告 | P0 |
| 趋势预警 | 总部 | 识别行业重大变化（政策、原材料价格等）并推送预警 | P2 |

#### 4.2.3 技术实现要点

- 使用通义千问（Qwen）**内置的联网搜索能力**，通过 `enable_search=True` 参数开启，无需自建搜索模块
- 详细实现方式：在调用千问 LLM 时传入 `enable_search=True` 参数，模型自动联网获取最新信息后生成回答
- 支持定期自动生成报告（日报/周报/月报）

### 4.4 加盟商培训

#### 4.4.1 概述

面向新加盟商提供系统化的 AI 辅助培训，帮助快速掌握公司制度、菜品知识、运营规范等内容。

#### 4.4.2 功能列表

| 功能 | 用户 | 描述 | 优先级 |
|------|------|------|--------|
| 知识库问答 | 总部、加盟商 | 基于 RAG 的公司制度、政策、流程问答 | P0 |
| 菜品知识学习 | 加盟商 | 学习公司菜品配方、制作工艺、标准化流程 | P0 |
| 培训课程管理 | 总部 | 上传、管理培训材料（文档、视频、PPT） | P1 |
| 学习进度追踪 | 总部、加盟商 | 记录学习进度，标记已完成/未完成内容 | P1 |
| 在线考核 | 总部、加盟商 | AI 出题并自动批改，检验学习效果 | P2 |

#### 4.4.3 知识库建设

- 知识分类：公司制度、政策法规、菜品知识、运营流程、SOP 标准
- **文档格式支持**：
  - **PDF**：支持文字型 PDF 的文本提取与向量化
  - **Word（.doc/.docx）**：支持文档段落解析与格式保留
  - 其他格式（PPT、Excel、图片、视频）作为辅助补充
- 文档解析流程：原始文件 → 文本提取 → 文本分块（chunking）→ Embedding 向量化 → 存入 Milvus
- **前端上传界面**：Vue 3 前端提供文档上传页面，支持拖拽或选择文件上传，上传后自动触发后端解析与向量化流程
- 更新机制：知识库内容更新后自动重新向量化

#### 4.4.4 RAG 实现要求

- 使用 Milvus 向量数据库存储文档 Embedding
- 结合 Qwen 的 Embedding 模型进行向量化（768 维）
- 检索策略：混合检索（向量相似度 + 关键词匹配）
- 支持多轮对话中的上下文引用溯源

### 4.5 风评分析

#### 4.5.1 概述

基于数据库中预置的模拟评论数据，利用 AI 分析各门店口碑表现，提炼洞察、生成回复建议。评论数据不对外部平台进行真实采集，通过模拟数据集模拟各平台（美团、饿了么、大众点评等）的用户评论。

#### 4.5.2 数据说明

评论数据使用**模拟数据**，存储在 MySQL，通过初始化脚本批量生成：
- 覆盖多个维度：评分（1-5 星）、评论内容、评论时间、所属门店、平台来源
- 评论内容由 AI（LLM）根据预设模板和菜品信息批量生成，覆盖正面、负面、中性评论
- 数据量级：每店数百至上千条评论，支持按需扩充
- 支持按门店、平台、评分等维度筛选查询

#### 4.5.3 功能列表

| 功能 | 用户 | 描述 | 优先级 |
|------|------|------|--------|
| 评论查询与筛选 | 总部、加盟商 | 按门店、平台、评分、时间等维度查询模拟评论数据 | P0 |
| 情感分析 | 总部、加盟商 | 利用 AI 对评论进行正面/负面/中性情感分类 | P0 |
| 标签提取 | 总部、加盟商 | 自动提取评论中的高频关键词和话题标签 | P0 |
| 差评预警 | 加盟商 | 差评实时推送，提醒及时回复处理 | P1 |
| 竞品风评对比 | 总部 | 对比本品牌与竞品的评分、口碑差异（模拟数据） | P2 |
| 风评趋势日报 | 总部、加盟商 | 每日风评总结报告，展示评分变化与热点话题 | P1 |
| AI 回复建议 | 加盟商 | 自动生成差评回复建议，提高回复效率 | P1 |

#### 4.5.4 分析维度

- 综合评分趋势（日/周/月）
- 菜品评价分析（口味、份量、新鲜度等）
- 服务评价分析（出餐速度、服务态度等）
- 环境评价分析（卫生、装修等）
- 竞品对比分析

### 4.6 智能备菜（暂不实现）

> **说明**：本模块暂不实现，以下为需求设计参考，待后续版本开发。

#### 4.6.1 概述

面向加盟商，基于多维度数据自动计算次日/当日的备货量，生成采购单并预警缺货风险。

#### 4.6.2 数据说明

智能备菜的预测模型输入数据均为**模拟生成数据**，存储在 MySQL：
- 历史销量：各菜品的历史销售记录由初始化脚本按门店、日期批量生成
- 天气数据：调用外部免费天气 API 获取历史/预报数据
- 节假日：内置日历数据，标注法定节假日与调休
- 外卖单量：随销量数据同步生成
- 促销活动：手动录入或预置活动模板

#### 4.6.3 功能列表

| 功能 | 用户 | 描述 | 优先级 |
|------|------|------|--------|
| 销量预测 | 加盟商 | 基于历史销量、天气、节日、外卖单量等因素预测次日销量 | P0 |
| 备货计算 | 加盟商 | 自动计算各菜品/食材的备货量 | P0 |
| 采购单生成 | 加盟商 | 根据备货计算结果自动生成采购清单 | P0 |
| 缺货预警 | 加盟商 | 识别库存不足风险并提前预警 | P0 |
| 损耗分析 | 加盟商 | 统计食材损耗率，优化备货精度 | P1 |
| 历史对比 | 加盟商 | 展示预测销量与实际销量的对比，持续优化算法 | P2 |

#### 4.6.4 预测模型输入数据

| 数据维度 | 说明 | 来源 |
|----------|------|------|
| 历史销量 | 过去 30/90/180 天的各菜品销售量 | **模拟数据** |
| 天气数据 | 气温、降水、空气质量等 | 外部天气 API |
| 节假日 | 法定节假日、周末、特殊日期 | 日历数据 |
| 外卖单量 | 各平台外卖订单量及趋势 | **模拟数据** |
| 促销活动 | 当前进行的优惠活动、满减等 | 手动录入 |
| 季节性 | 食材的季节性供应与需求变化 | 运营经验数据 |

#### 4.6.5 技术实现

- 使用简单线性回归或时间序列模型进行基础预测（项目已集成 `simpleLineRegressionTest.py`）
- 后期可引入更复杂的预测模型提升精度
- 采购单支持自定义供应商模板

### 8.2 数据生成脚本

模拟数据生成脚本位于 `doc/sql/` 目录：
- `schema.sql` — 10 张业务表的完整 DDL（门店、菜品、订单、订单明细、营业汇总、评论、库存、采购、用户等），其中库存、采购相关表因智能备菜模块暂不实现，已注释
- `generate_data.py` — 数据生成与批量插入脚本，支持自定义门店数量、日期范围、数据库配置
- `README.md` — 使用说明

生成的数据特征：
- **门店**: 500 家，均匀分布全国 31 个省级行政区，命名格式 `省份+城市+xxx店`
- **订单**: 每店每日数十笔订单，每条记录区分微信支付/支付宝支付/现金支付，每条订单含 1~4 道菜品
- **数据周期**: 1 年（2025 年全年），含节假日倍率、季节效应、天气影响
- **营业额**: 每店每日 1000~3000 元，客单价 22~38 元
- **菜品**: 31 道中式快餐，按 popularity 权重随机选菜
